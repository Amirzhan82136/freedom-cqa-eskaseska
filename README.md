# Freedom CQA: контроль качества диалогов операторов

Хакатон Freedom Broker · команда EskaSeska.

Система оценивает чаты и звонки операторов по чек-листу из 8 критериев. **ИИ предлагает оценку и показывает доказательства (номера реплик), а финальное решение принимает человек.**

## Результаты

| Набор | Файл | Итог |
|---|---|---|
| DEV (60 чатов + 5 звонков, RU/KZ/EN) | `results/dev/results.json` | 65/65 оценено, 0 ошибок, средний балл 85,54, грубых ошибок 5 |
| PROD (10 контрольных чатов) | `results/prod/results.json` | — |

Формат файлов — JSON 1.0 из приложения к гайду (`docs/`): одна запись на диалог, ровно 8 критериев, `evidence_turns` по исходному массиву транскрипта, при сбое — `status: "error"`, а не ноль.

## Как устроено

1. **Загрузка.** Диалоги берутся из API организаторов (`GET` с параметром `group_id`). Реплики нумеруются с 1 по всему транскрипту: клиент, оператор, бот, события. Время звонков (ISO 8601) переводится в секунды от начала, записи звонков сохраняются для плеера.
2. **Оценка ИИ.** Модель получает чек-лист и транскрипт и отвечает строго в JSON по схеме: значение, объяснение и номера реплик по каждому критерию.
3. **Проверка ответа кодом.** Все критерии на месте, значения допустимые, такие реплики существуют. Иначе повторный запрос; если не удалось — `status: "error"`.
4. **Балл считает код, а не ИИ:** Σ(вес × доля) / Σ весов применимых критериев × 100. N/A исключается из расчёта, `critical` передаётся отдельным флагом.
5. **Сайт.** Разбор диалога с доказательствами, плеер звонков, апелляции, редактор чек-листа, аналитика и оценка нового диалога в реальном времени.

**Модель.** Google Gemini через API (`gemini-3.6-flash`, при исчерпании дневного лимита бесплатного тарифа — `gemini-3.8-flash`, `gemini-3.5-flash-lite`). Провайдер меняется в `.env` (`CQA_PROVIDER=gemini` или `claude`), поддерживается Claude Opus 5.5. Режим `external_api`.

## Структура

| Файл | Назначение |
|---|---|
| `checklist.py` | 8 критериев: коды, значения, веса, описания для ИИ |
| `scoring.py` | формула итогового балла |
| `evaluate.py` | загрузка, оценка ИИ, проверка ответа, расчёт балла, `results.json` |
| `validate.py` | проверка `results.json` по правилам гайда |
| `test_scoring.py` | тесты формулы (пример из гайда = 85,38) и нумерации реплик |
| `server.py` | сервер сайта (стандартная библиотека Python) |
| `web/` | сайт: HTML, CSS, JavaScript без библиотек |
| `cache/` | сохранённые ответы модели (повторный запуск не тратит запросы) |
| `data/demo*`, `tools/make_demo.py` | демо-наборы для показа интерфейса (диалоги и оценки составлены вручную, не данные организаторов) |
| `презентация/` | слайды проекта |

## Запуск

```bash
pip3 install -r requirements.txt
cp .env.example .env          # ключ модели и ссылка API организаторов
python3 test_scoring.py
python3 evaluate.py --set dev  # или --set prod --group-id <значение>
python3 validate.py results/dev/results.json
python3 server.py              # сайт, откроется в браузере
```
