# CQA: контроль качества диалогов (команда EskaSeska)

Хакатон Freedom Broker. Система проверяет разговоры операторов с клиентами (чаты и звонки) по чек-листу из 8 критериев.

**ИИ предлагает оценку и показывает доказательства, а решение принимает человек.**

## Что внутри

| Файл | Что делает |
|---|---|
| `checklist.py` | 8 критериев: коды, допустимые значения, веса, описания |
| `scoring.py` | формула итогового балла (балл считает код, а не ИИ) |
| `evaluate.py` | главный скрипт: загрузка, оценка ИИ, проверка, балл, сохранение |
| `validate.py` | проверка `results.json` перед отправкой |
| `server.py` | сервер сайта: живая оценка нового диалога, загрузка DEV/PROD из API по кнопке, редактор чек-листа |
| `checklist.json` | рабочий чек-лист, который меняют на сайте (появляется после первого сохранения) |
| `test_scoring.py` | тесты формулы и нумерации реплик |
| `web/` | сайт для проверяющего (HTML + CSS + JS, без библиотек) |
| `results/dev/results.json`, `results/prod/results.json` | результаты для жюри |
| `data/demo/`, `data/demo-prod/` | демо-наборы: DEMO (12 диалогов: 6 чатов + 6 звонков) и «PROD (пример)» (10 диалогов: 5 + 5) на русском, казахском и английском. Диалоги и оценки придуманы вручную, это не данные организаторов и не оценки ИИ |
| `tools/make_demo.py` | создаёт демо-наборы; звонки озвучены нейросетевыми голосами Microsoft (edge-tts) |
| `web/img/` | логотип Freedom |

## Установка (один раз)

```bash
pip3 install -r requirements.txt
cp .env.example .env
```

Откройте `.env` и впишите `ANTHROPIC_API_KEY` (ключ Claude API). Если данные выдаются через API организаторов, впишите также `CQA_API_URL` и `CQA_API_TOKEN`. Файл `.env` в git не попадает.

Без API диалоги можно просто положить `.json`-файлами в `data/dev/` или `data/prod/`.

## Запуск

```bash
python3 test_scoring.py               # тесты формулы (пример из гайда даёт 85.38)
python3 evaluate.py --set dev         # оценить DEV -> results/dev/results.json
python3 validate.py results/dev/results.json
```

Для пробы можно оценить только первые 3 диалога: `python3 evaluate.py --set dev --limit 3`.

**PROD (за час до конца), по порядку:**

1. Получить 10 контрольных чатов: положить файлы (`.json`, `.jsonl` или `.csv`) в `data/prod/` или вписать адрес API в `.env` (подробно в [data/README.md](data/README.md)).
2. Дважды щёлкнуть **«Оценить диалоги.command»** и написать `prod`. Он сам проверит, как прочитались чаты (`--check`), оценит их, проверит файл и сделает коммит.
3. В GitHub Desktop нажать **Push origin**.

То же самое вручную:

```bash
python3 evaluate.py --set prod --check
python3 evaluate.py --set prod
python3 validate.py results/prod/results.json
git add results/prod/results.json
git commit -m "PROD результаты"
git push
```

`--check` ничего не оценивает и не тратит ключ: только показывает, сколько диалогов найдено и как распознаны реплики. Запускайте его первым.

Если прогон оборвался, просто запустите ту же команду ещё раз. Уже оценённые диалоги берутся из кэша `cache/`, повторно модель не спрашивается.

## Сайт (живой продукт)

Двойной клик по **«Запустить сайт.command»** или команда:

```bash
python3 server.py
```

Браузер откроется сам. Разделы: **Диалоги**, **Анализ разговора** (по клику на диалог), **Чек-листы**, **Апелляции**, **Аналитика**.

Что можно показать жюри вживую:
- **«Оценить новый диалог»**: вставить любой текст диалога, и ИИ оценит его по текущему чек-листу за полминуты. Результат появится в наборе «Живая оценка».
- **«Загрузить и оценить DEV / PROD»**: сайт сам скачает набор из API организаторов, оценит его с полосой прогресса и создаст `results/<набор>/results.json`.
- **Чек-листы**: добавить свой критерий, изменить описание или вес. Баллы сразу пересчитываются. Новый критерий ИИ оценит по кнопке «Переоценить по текущему чек-листу». Критерии из гайда удалить нельзя, а `results.json` для жюри всегда считается по чек-листу гайда.
- **Только нарушения**: фильтр на странице диалогов, у каждого диалога есть объяснение и ссылка на реплику.
- **Апелляция**: кнопка «Оспорить оценку», решение принимается в разделе «Апелляции».

Без сервера (`python3 -m http.server`) сайт тоже открывается, но только для просмотра. Сервер слушает только этот компьютер (127.0.0.1) и не отдаёт `.env` и кэш.

## Как это работает

1. **Загрузка.** Диалоги берутся из API или из `data/<набор>/`. Реплики нумеруются с 1 по **всему** массиву: клиент, оператор, бот и события.
2. **ИИ.** Модель Claude (`claude-opus-5-5`) получает чек-лист и транскрипт вида `[5] Оператор (00:14): ...`. Она возвращает JSON строго по схеме: значение, объяснение и номера реплик по каждому критерию.
3. **Проверка.** Код проверяет, что в ответе есть все 8 критериев, значения допустимые, а реплики существуют. Если что-то не так, делается до 3 попыток, после чего диалог получает `status: "error"`, а не ноль.
4. **Балл.** Считается функцией `calc_score`: Σ(вес × доля) / Σ весов применимых критериев × 100. N/A исключается, `critical` идёт отдельным флагом.
5. **Сайт.** Показывает оценку и доказательства. Человек может оспорить оценку и зафиксировать финальную.

Температуру 0 задать нельзя: новые модели Claude этот параметр не принимают. Стабильность обеспечивают фиксированная инструкция, строгая JSON-схема ответа и проверка кодом.
