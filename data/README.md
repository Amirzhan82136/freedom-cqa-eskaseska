# Папка с диалогами

| Папка | Что это |
|---|---|
| `data/dev/` | сюда положить DEV от организаторов (60 чатов + 5 звонков) |
| `data/prod/` | сюда положить PROD (10 контрольных чатов), их выдают за час до конца |
| `data/demo/`, `data/demo-prod/` | наши демо-наборы для показа сайта (не данные организаторов) |

Данные организаторов в git не попадают (см. `.gitignore`). В репозиторий идут только результаты в `results/`.

## Два способа получить данные

**1. Через API организаторов.** Впишите в `.env` строки `CQA_API_URL=...` и, если нужен, `CQA_API_TOKEN=...`. Скрипт скачает диалоги сам и сохранит копию в `data/<набор>/api_dump.json`.

**2. Файлами.** Просто положите файлы в `data/dev/` или `data/prod/`. Подходят:
- `.json`: список диалогов или `{"items": [...]}`, или один диалог в файле;
- `.jsonl`: один диалог на строку;
- `.csv`: одна реплика на строку, с колонками `conversation_id`, `role` (или `speaker`), `text`.

В диалоге скрипт сам находит ID (`conversation_id` / `id`), реплики (`transcript` / `messages` / `turns`), роль (`role` / `speaker` / `author` / `sender`) и текст (`text` / `content` / `message`).

## Сначала проверка, потом оценка

```bash
python3 evaluate.py --set prod --check
```

Эта команда ничего не оценивает и не тратит ключ. Она показывает, сколько диалогов найдено, сколько реплик в каждом и какие роли распознаны. Если пишет «ПРОБЛЕМА», значит формат организаторов отличается, и нужно поправить чтение в `evaluate.py` (функция `normalize_dialog`).

Удобнее всего дважды щёлкнуть по **«Оценить диалоги.command»**: он сделает проверку, оценку, валидацию и коммит по шагам.
